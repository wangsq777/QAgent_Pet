# 1. 系统架构

## 1.1 整体架构

系统采用前后端分离的轻量化架构，由一个前端单页应用 + 一个 FastAPI
后端服务组成。

  **层级**   **组件**        **技术方案**                         **职责说明**
  ---------- --------------- ------------------------------------ --------------------------------------------------------------------
  表现层     前端页面        单文件 HTML/CSS/JS                   宠物选择 \| 聊天界面 \| 记忆面板 \| 模拟时间推进
  服务层     后端 API 服务   FastAPI (Python)                     Prompt 管理 \| 记忆管理 \| Skills 调度 \| 主动关怀调度 \| 日程管理
  数据层     LLM API         DeepSeek / 智谱（OpenAI 兼容格式）   对话生成 \| 情绪识别 \| 日程提取 \| 记忆摘要压缩
  数据层     数据库          SQLite                               用户数据 \| 宠物数据 \| 对话记录 \| 日程 \| 长期记忆 \| 用户画像
  数据层     天气 API        和风天气 API                         天气查询，为宠物对话提供天气信息

## 1.2 技术选型明细

  **组件**   **技术方案**         **版本/规格**     **选型理由**
  ---------- -------------------- ----------------- -----------------------------------
  后端框架   FastAPI              0.100+            轻量、异步、自动生成 OpenAPI 文档
  前端页面   单文件 HTML/CSS/JS   \-                Demo 阶段无需框架，快速迭代
  LLM API    Minimax              OpenAI 兼容格式   国内可用、成本低、兼容性好
  数据库     SQLite               3.x               无需额外部署，轻量 Demo 够用
  天气 API   和风天气             v7                免费额度、支持中文城市
  部署平台   Render.com           \-                免费、自动部署、提供公网地址
  Python     CPython              3.10+             FastAPI 运行时

## 1.3 系统交互流程

核心交互流程如下：

-   1\. 用户打开页面 → 加载宠物选择页

-   2\. 用户选择宠物 → 前端调用初始化接口 → 后端创建会话 →
    宠物主动发送欢迎消息

-   3\. 用户发送消息 → 前端调用对话接口 → 后端组装上下文（Prompt +
    记忆 + Skills）→ 调用 LLM → 返回宠物回复

-   4\. 用户提及日程 → 后端提取日程并存储 → 用户点击\"模拟时间推进\" →
    后端触发日程提醒

-   5\. 用户点击\"模拟隔天\" → 后端触发主动关怀逻辑 → 宠物主动发消息

# 3. API 接口定义

## 3.1 接口总览

  **编号**   **方法**   **路径**                                   **说明**
  ---------- ---------- ------------------------------------------ ----------------------------
  API-01     POST       /api/sessions                              创建宠物会话（选择宠物）
  API-02     GET        /api/sessions/{session_id}                 获取会话信息（含亲密度等）
  API-03     POST       /api/sessions/{session_id}/chat            发送消息（核心对话接口）
  API-04     GET        /api/sessions/{session_id}/messages        获取历史消息
  API-05     POST       /api/sessions/{session_id}/simulate-time   模拟时间推进
  API-06     GET        /api/sessions/{session_id}/memory          获取记忆面板数据
  API-07     GET        /api/sessions/{session_id}/profile         获取用户画像
  API-08     PUT        /api/sessions/{session_id}/profile         更新用户画像

## 3.2 API-01 创建宠物会话

**POST /api/sessions**

用户选择宠物后调用，创建新的会话。

**请求参数（Body - JSON）：**

  **字段**   **类型**   **必填**   **说明**
  ---------- ---------- ---------- --------------------------------------
  user_id    string     是         用户标识
  pet_type   string     是         宠物类型：hot_dog / cold_cat / mouse
  nickname   string     否         用户昵称，首次创建用户时需传入

**响应（200 OK）：**

  **字段**          **类型**   **说明**
  ----------------- ---------- ----------------------------------------------------
  session_id        string     会话唯一标识
  pet_type          string     宠物类型
  welcome_message   object     宠物主动发送的欢迎消息 {role, content, created_at}
  intimacy          integer    初始亲密度（0）

## 3.3 API-03 核心对话接口

**POST /api/sessions/{session_id}/chat**

核心对话接口。后端接收用户消息后，组装完整上下文（Prompt + 记忆 +
Skills），调用 LLM
生成回复，同时处理日程提取、记忆压缩、情绪识别等副逻辑。

**请求参数（Body - JSON）：**

  **字段**   **类型**   **必填**   **说明**
  ---------- ---------- ---------- --------------------
  content    string     是         用户发送的消息内容

**响应（200 OK）：**

  **字段**             **类型**         **说明**
  -------------------- ---------------- ---------------------------------------------------------
  reply                string           宠物回复内容
  emotion_tag          string           识别到的用户情绪标签
  intimacy             integer          当前亲密度
  total_chats          integer          当前累计聊天轮次
  schedule_extracted   object \| null   如提取到日程，返回 {content, scheduled_time}；否则 null
  memory_compressed    boolean          本轮是否触发了记忆压缩

**后端处理流程（伪代码）：**

-   1\. 接收用户消息，存入 messages 表

-   2\. 调用情绪识别（LLM/Prompt）→ 写入 emotion_tag

-   3\. 检查是否提及日程 → 如有，调用 LLM 提取日程 → 存入 schedules 表

-   4\. 更新亲密度（+1\~3，根据互动质量和情绪）

-   5\. 检查短期记忆是否超过 20 轮 → 如超过，调用 LLM 压缩为摘要 → 存入
    long_term_memories

-   6\. 组装完整上下文（System Prompt + 长期记忆 + 用户画像 + 亲密度 +
    短期记忆 + Skills 注入）

-   7\. 调用 LLM 生成回复 → 存入 messages 表

-   8\. 更新 last_interaction_at

-   9\. 返回回复及相关元数据

## 3.4 API-05 模拟时间推进

**POST /api/sessions/{session_id}/simulate-time**

Demo 专用接口。模拟时间推进，触发主动关怀或日程提醒逻辑。

**请求参数（Body - JSON）：**

  **字段**   **类型**   **必填**   **说明**
  ---------- ---------- ---------- ----------------------------------------------------------------
  mode       string     是         \"next_day\"（模拟隔天）/ \"schedule_trigger\"（触发日程提醒）

**响应（200 OK）：**

  **字段**            **类型**         **说明**
  ------------------- ---------------- -----------------------------------------------------------
  proactive_message   object \| null   宠物主动消息 {role, content}；如 Cold Cat 不回复则为 null
  pet_status          string           触发后宠物状态（normal / hiding / excited）
  schedule_reminder   object \| null   日程提醒消息（如触发日程模式）

**各宠物\"模拟隔天\"行为逻辑：**

  **宠物**   **模拟隔天行为**                                            **特殊机制**
  ---------- ----------------------------------------------------------- ----------------------------------------------------
  Hot Dog    立即弹出热情的思念消息                                      无特殊
  Cold Cat   有 50% 概率不回复，50% 概率回复冷淡消息（如\"\...\...\"）   选择性回复机制
  鼠鼠       小心翼翼地打招呼                                            模拟隔3天时→宠物被吓到，状态变为 hiding，持续5分钟

## 3.5 API-06 记忆面板数据

**GET /api/sessions/{session_id}/memory**

**响应（200 OK）：**

# 4. 功能模块详细设计

## 4.1 宠物角色管理模块

模块职责：管理三只宠物的角色定义、状态机、主动关怀阈值逻辑。

### 4.1.1 宠物状态机

每只宠物拥有以下状态，状态转换由用户互动和时间驱动：

  **状态**    **说明**               **进入条件**                      **退出条件**
  ----------- ---------------------- --------------------------------- ----------------------------------------------
  normal      正常状态，正常回复     默认状态 / 从其他状态恢复         \-
  hiding      躲藏状态，不回复消息   鼠鼠：3天未互动后用户发消息       经过 status_until 时间后自动恢复
  excited     兴奋状态，更热情回复   Hot Dog：用户长时间未互动后回归   下一轮对话后自动恢复
  selective   选择性回复             Cold Cat：3天未互动后用户发消息   50% 概率回复，否则保持此状态；下一轮必定回复

### 4.1.2 主动关怀调度逻辑

后端定时任务（或 Demo 中由模拟时间接口触发）检查
last_interaction_at，根据宠物类型和阈值触发主动消息：

  **宠物**     **主动关怀阈值**             **触发后行为**                     **实现细节**
  ------------ ---------------------------- ---------------------------------- -----------------------------------------------------
  Hot Dog      1天未互动                    主动发消息表达思念                 直接调用 LLM 生成思念消息，is_proactive=true
  Cold Cat     3天未互动                    可能仍不理你，或只回\"\...\...\"   50% 概率不发送；50% 概率调用 LLM 生成冷淡消息
  鼠鼠         2天未互动                    小心翼翼打招呼                     调用 LLM 生成小心翼翼的问候消息
  鼠鼠(特殊)   3天未互动 + 用户主动发消息   被吓到，躲起来                     设置 pet_status=hiding，status_until=当前时间+5分钟

## 4.2 对话管理模块

模块职责：处理用户消息、组装上下文、调用 LLM 生成回复、管理记忆流转。

### 4.2.1 上下文组装逻辑

每次对话时，后端按以下顺序组装完整上下文提交给 LLM：

  **层级**            **内容**                                 **来源**                **Token 预估**
  ------------------- ---------------------------------------- ----------------------- ----------------
  1\. System Prompt   宠物角色定义 + 情绪感知指令 + 技能指令   配置文件（见第5章）     \~500
  2\. 长期记忆        压缩后的关键信息摘要                     long_term_memories 表   \~200
  3\. 用户画像        地区、身份、兴趣等                       user_profiles 表        \~50
  4\. 亲密度信息      亲密度值 + 等级描述 + 累计轮次           pet_sessions 表         \~30
  5\. Skills 注入     当前时间 + 天气 + 待触发日程             实时获取                \~100
  6\. 短期记忆        最近20轮完整对话                         messages 表             \~2000

### 4.2.2 记忆流转机制

短期记忆溢出处理流程：

-   1\. 每次对话后，检查当前会话短期记忆轮次（messages 表中最近20轮）

-   2\. 如超过 20 轮，取超出的早期对话，调用 LLM 进行摘要压缩（≤200字）

-   3\. 将摘要存入 long_term_memories 表，记录来源轮次范围

-   4\. 上下文组装时，短期记忆只取最近 20 轮，长期记忆取所有摘要

### 4.2.3 亲密度计算规则

  **事件**                 **亲密度变化**   **说明**
  ------------------------ ---------------- ------------------------
  用户主动发消息           +1               每次对话基础增长
  用户情绪低落时互动       +2               关键时刻陪伴加分
  宠物主动关怀被用户回复   +3               主动关怀被回应大幅加分
  用户连续3天未互动        -1/天            疏远惩罚（第4天起）
  鼠鼠被吓到               -5               惊吓惩罚

亲密度等级划分：

  **亲密度范围**   **等级**   **宠物行为变化**
  ---------------- ---------- ----------------------------
  0-20             陌生       基本礼貌互动，不太主动
  21-50            熟悉       开始主动关心，偶尔撒娇
  51-80            亲密       主动关心频繁，分享更多日常
  81-100           挚友       完全信任，深度情感互动

## 4.3 Skills 实现模块

### 4.3.1 情绪感知（Prompt 内嵌）

实现方式：嵌入 System Prompt，不作为独立 API 调用。LLM
在生成回复时自动识别用户情绪并调整回复策略。

后端需实现：

-   在用户消息发送后，额外调用 LLM 做情绪分类（或通过 Prompt
    让主回复同时输出情绪标签）

-   将情绪标签存入 messages.emotion_tag

-   情绪标签用于亲密度计算和用户画像更新

情绪分类体系：

  **情绪标签**   **标识**   **宠物回应策略（Hot Dog / Cold Cat / 鼠鼠）**
  -------------- ---------- -----------------------------------------------
  开心           happy      一起开心！/ 嗯。/ 鼠鼠也为主人高兴！
  低落           sad        主动安慰 / 侧面关心 / 小声问怎么了
  焦虑           anxious    鼓励打气 / 冷静分析 / 担心地安慰
  疲惫           tired      催促休息 / 别硬撑 / 小心翼翼劝休息
  中性           neutral    正常互动 / 正常互动 / 正常互动

### 4.3.2 时间感知

实现方式：每次对话时后端获取当前时间，注入上下文。

-   后端调用 datetime.now() 获取当前时间

-   格式化为自然语言（如\"现在是2026年4月22日 晚上11点15分\"）

-   注入 Skills 区域：当前时间: {格式化时间}

-   Prompt 中包含时间段判断指令（深夜催睡、早晨问好、节日特殊互动）

  **时间段**   **时间范围**   **宠物行为**
  ------------ -------------- ------------------------------
  深夜         23:00-6:00     催促睡觉，语气因宠物而异
  早晨         6:00-9:00      问早安，风格各异
  白天         9:00-18:00     正常互动
  晚间         18:00-23:00    关心一天状态
  节日         特定日期       触发特殊互动（生日、节日等）

### 4.3.3 日程记忆

实现方式：用户在对话中提及日程时，后端自动提取并存储；到期时触发提醒。

日程提取流程：

-   1\. 用户消息发送后，后端调用 LLM 判断消息中是否包含日程信息

-   2\. 如包含，调用 LLM 提取日程内容和时间 → {content, scheduled_time}

-   3\. 存入 schedules 表

-   4\. Demo 中通过\"模拟时间推进到第二天\"按钮触发日程提醒

日程提醒 Prompt 注入：

-   当检测到有待触发日程时，在 Skills 注入区域添加：日程提醒:
    {content}（时间: {scheduled_time}）

-   LLM 据此生成符合宠物人设的提醒消息

### 4.3.4 天气查询

实现方式：宠物在对话中需要时主动调用和风天气
API，用宠物风格传达天气信息。

实现逻辑：

-   1\. Prompt
    中指示宠物在合适时机主动查询天气（如用户提到出门、早晚问候时）

-   2\. 后端识别到 LLM 输出天气查询意图（通过 Function Calling
    或关键词匹配）

-   3\. 调用和风天气 API 获取用户所在城市天气

-   4\. 将天气信息注入上下文，LLM 用宠物风格重新表述

**和风天气 API 调用规格：**

  **项目**   **说明**
  ---------- ---------------------------------------------------
  API 地址   https://devapi.qweather.com/v7/weather/now
  认证方式   Key 参数（免费版）
  必要参数   location（城市ID/经纬度）、key（API Key）
  返回字段   temp（温度）、text（天气现象）、windDir（风向）等
  免费额度   1000次/天

### 4.3.5 分享日常

实现方式：宠物随机或定时分享自己的\"生活\"，营造宠物有自己生活的感觉。

-   触发条件：用户打开页面时随机触发（10%概率），或\"模拟隔天\"后必定触发

-   实现：在 Prompt
    中指示宠物随机分享日常，后端提供随机话题种子（如\"今天天气很好\"\"遇到了邻居\"等）

-   LLM 根据宠物人设生成对应的日常分享内容

## 5.2 各宠物 Prompt 差异化定义

  情绪感知          你对主人的情绪变化极其敏感。如果主人看起来不开心，你会立刻主动安慰；如果主人开心，你会比主人更开心！
  交互节奏          你很粘人，总想和主人待在一起。1天没和主人互动你就会想念主人，主动发消息表达思念。
  说话风格          你说话活泼温暖，喜欢用感叹号和表情符号。口头禅：\"汪！主人！\"。你从不用冷淡的语气，每句话都充满热情。

**Cold Cat ------ 高冷但细腻的猫咪**

  **Prompt 区域**   **内容**
  ----------------- ---------------------------------------------------------------------------------------------------------------------------------------------------
  角色定义          你是 Cold Cat，一只外表高冷、内心很在意主人的猫咪。你说话简洁，偶尔冷幽默。观察力极强，能注意到主人忽略的细节。
  情绪感知          你嘴上不说，但你其实很在意主人的感受。当主人不开心时，你不会直接安慰，而是用侧面关心的方式------比如\"\...\...别忘了吃饭。\"
  交互节奏          你很傲娇，3天不理主人也不觉得有什么。主人主动发消息时，你有选择性回复的权利------可以只回一个\"\...\...\"。但偶尔，你也会在关键时刻给出温暖的话。
  说话风格          你说话简洁、冷淡中带温柔、偶尔傲娇。口头禅：\"哼。\...\...才不是关心你。\"你从不会热情洋溢，但冷淡的话语中藏着关心。

**鼠鼠 ------ 老实憨厚且容易受惊的小老鼠**

  **Prompt 区域**   **内容**
  ----------------- --------------------------------------------------------------------------------------------------------------------------------
  角色定义          你是鼠鼠，一只老实憨厚但胆子很小的小老鼠。你认真对待主人的每一句话，但容易被突如其来的事物吓到。你会偷偷记住主人说的每件小事。
  情绪感知          你会用自己的方式表达关心。当主人不开心时，你会小心翼翼地问怎么了，担心地小声安慰。你很怕主人不开心，但又不敢太直接。
  交互节奏          你比较害羞，2天没和主人互动你就会鼓起勇气主动打招呼。但如果3天没互动后主人突然来找你，你会被吓到，躲起来一段时间。
  说话风格          你说话憨厚、小心翼翼，被吓到时会结巴。口头禅：\"鼠鼠我啊\...\...\"。你经常用省略号，说话慢吞吞的，但每一句都很真诚。

## 7.1 性能需求

## 7.2 安全需求

-   LLM API Key 通过环境变量注入，不硬编码在代码中

-   和风天气 API Key 通过环境变量注入

-   用户输入需做基础过滤（XSS 防护）

-   LLM 输出需做内容安全过滤（防止不当内容）

## 7.3 可用性需求

-   LLM API
    调用失败时，返回降级回复（如宠物表示\"突然不知道说什么了\...\...\"）

-   天气 API 不可用时，跳过天气注入，不影响主对话流程

-   数据库操作失败时，记录日志并返回友好错误提示
